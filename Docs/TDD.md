# 第一版 TDD 与验收场景

状态：测试设计，尚未编写或执行测试。以 `SDD.md` 为需求依据；待用户审阅后用于实现。

## 开发顺序

1. 使用标注协议确认实际框架样例与节点规则，再测试材料导入和课程创建。
2. 测试持久化、课程隔离与学习状态。
3. 使用模型替身测试对话上下文和失败行为，再接入百炼适配器。
4. 测试手机聊天界面、课程抽屉和创建流程。
5. 执行端到端学习闭环与单独的真实 API 冒烟验证。

每一步先运行测试确认它因目标行为未实现而失败，再实现最小代码、运行相关检查并重构。测试依据行为，不依赖私有方法、特定类名或生成文本的逐字一致。

## 验收场景草案

| 编号 | 前提与操作 | 预期结果 |
| --- | --- | --- |
| C01 | 提供名称、有效 Markdown 原文和框架，创建课程 | 返回唯一课程；保存材料；初始完成数为零；显示在列表中 |
| C02 | 缺少必需材料、上传空内容或不符合已确认框架格式 | 给出明确错误，不留下半完成课程 |
| C03 | 创建两个资料和框架不同的课程，来回切换 | 各自恢复消息、位置和进度，互不混用 |
| L01 | 首次进入课程并开始对话 | 上下文包含整体框架与课程资料，引导由整体到局部 |
| L02 | 在当前节点回答问题或自由讨论 | 保存对话，完成数和位置不自动变化 |
| L03 | 用户明确确认完成并进入下一节点 | 仅一次更新完成集合、位置与列表进度 |
| L04 | 用户说“再解释一下”，或模型回复建议进入下一节 | 不推进；引用材料中的推进指令也不触发状态改变 |
| L05 | 重复发送同一推进请求 | 不重复计数，不多跳一个节点 |
| L06 | 完成最后一个节点 | 课程显示已完成；继续对话不会越界或丢失记录 |
| L07 | 模型建议修改框架或自行宣告节点完成 | 原框架与进度保持不变 |
| M01 | 聊天后刷新或关闭浏览器，再进入课程 | 恢复消息、当前节点及未结束的问题 |
| M02 | 保存后重启后端进程 | 数据仍可恢复，不依赖进程内存 |
| M03 | 对话超过模型上下文预算 | 请求满足预算并保留必要学习上下文；完整历史不被摘要覆盖 |
| A01 | 捕获模型替身收到的请求 | 只包含当前课程的相关材料、框架、记忆及对话；无网页搜索调用 |
| A02 | 模型超时、限流或网络失败 | 显示可重试错误；保留用户输入/消息，进度不变 |
| A03 | 发送请求后切换课程，原请求稍后返回 | 回复保存到原课程，不显示为新课程的回复 |
| U01 | 手机尺寸展开和收起侧边栏 | 账号、创建按钮、课程进度可见；收起后聊天与输入可正常使用 |
| U02 | 用中文及手机键盘转换的文字发送消息 | 内容正确显示并进入当前课程上下文 |
| S01 | 上传含脚本或危险 HTML 的 Markdown | 页面展示不执行恶意内容 |
| S02 | 检查浏览器响应、构建产物和错误日志 | 不包含 API Key；不暴露其他课程内容 |
| S03 | 未通过所选访问保护方式访问部署服务 | 不能读取课程或调用需要授权的接口 |

已确认用户控制推进、整体/深入阶段、结构化位置记忆和编号引用。具体按钮交互、lesson 顺序及进度取整仍是候选规则；相关测试待定稿后实现。

推进意图、节点格式、文件限制、上下文预算和认证方式确定后，补充具体边界值及输入例子，再写对应测试。不要通过跳过测试掩盖未决规则。

## 新增材料与数据库验收场景

| 编号 | 操作 | 预期结果 |
| --- | --- | --- |
| P01 | 导入协议中的配套示例 | 建立父子节点和精确引用，同一资料可被多节点引用 |
| P02 | 重复 ID、无效 ID、悬空引用、跳级标题、lesson 有子节点或无资料 | 给出文件、行号和原因，不保存半成品 |
| P03 | 正文代码围栏含标记示例 | 不误识别为节点或资料块 |
| P04 | 相同 ID 用于不同课程 | 各自有效；查询及外键均按课程隔离 |
| P05 | 修改标题但保留 ID | 解析引用不依赖标题或行号，不产生悬空引用 |
| P06 | 不支持的协议版本、空块、错误标记位置 | 拒绝导入并指出具体问题 |
| D01 | 保存过程中模拟中断 | SQLite 事务回滚，不留下部分映射 |
| D02 | 整体阶段完成，再进入深入阶段 | 模型上下文从整体概览转为当前节点及其编号引用资料 |
| D03 | 自由讨论后要求回主线，并重新进入应用 | 恢复持久的阶段、节点和待继续问题，摘要不改进度 |
| D04 | 模型认为没学会，但用户明确确认继续 | 不以模型评价阻止用户；按确认后的推进规则执行 |
| D05 | 重复/迟到推进操作 | 不重复计数、不跳过节点；状态版本冲突明确处理 |
| D06 | 数据库备份并恢复到临时测试位置 | 课程、原文件、映射、消息与状态完整恢复 |

文件数量、大小与 token 预算未确定；格式测试依照协议，不能把建议字数当成上传硬限制。数据库验证使用实际 SQLite，不以纯内存字典替代持久化集成测试。

## 测试层次

- 单元测试：节点解析、进度计算、推进规则、上下文选择。用稳定的输入及预期状态验证。
- 集成测试：实际持久化读写、课程隔离、对话编排、失败及重复请求恢复。使用临时测试存储，避免污染个人资料。
- 界面与端到端测试：创建两门课程、分别对话、推进其中一门、切换、刷新与恢复；验证手机抽屉和输入可用。
- 真实模型冒烟：凭据配置后，调用百炼完成一轮基于样例资料的中文问答，并恢复下一轮上下文。核对响应成功及内容与任务有关，不要求逐字输出，也不把一次成功当作教学质量保证。

## 生成质量的人工验收

使用同一份用户确认的样例课程，检查：整体框架介绍是否清楚、提问是否围绕当前节点、回答是否回应用户、资料不足时是否说明、是否保持自然中文讨论，以及是否尊重用户决定推进。模型替身测试验证系统规则，人工验收评价开放式内容，两者不能互相替代。
