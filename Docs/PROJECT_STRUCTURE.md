## 模块边界

- 按功能封装对象；复杂功能内部按业务对象、用例服务、接口拆分，小功能保持简单。
- HTTP 层负责协议与校验，不承载核心业务；前端 API 客户端与页面分开。
- 基础设施实现业务定义的接口；业务规则不绑定百炼或某个数据库。
- `bootstrap` 处理框架集成和依赖组装，不把用户上传的“学习框架”混同于软件框架。
- 测试按被测功能命名，实际运行配置必须覆盖选定目录。
- 文档、需求、原型集中在 `Docs`。重要决策记录背景、选择和后果；后续增加 API 文档和部署说明时也放在这里。
- 密钥、个人课程资料、运行日志、数据库和构建产物不提交 Git；选型后配置相应忽略规则。

## 开发管理流程

需求讨论 → 更新 SDD/决策记录 → 确认验收场景 → 失败测试 → 实现 → 重构 → 验证 → 审阅。

按功能拆分任务和提交，描述目的、变更与验证。当前优先讨论学习行为与进度，不启动应用实现。
