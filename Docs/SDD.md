# 个人 AI 学习教练：规格与设计

状态：讨论结果整理稿，待用户审阅。更新日期：2026-10-10。

## 1. 产品定位

面向个人、适合手机碎片时间使用的中文 AI 学习教练。用户先在外部通用大模型中，将已有知识整理成符合自身思考习惯的框架，再将 Markdown 原文和框架导入本应用。应用依托通义千问（阿里云百炼）进行自然讲解、提问和讨论，沿既定框架从整体逐步深入，并保存学习位置。

第一版的核心价值是按框架持续学习及恢复上下文。用户决定何时进入下一阶段。应用不修改框架，也不以考试结果限制推进。

## 2. 已确认的第一版范围

| 功能 | 行为 |
| --- | --- |
| 创建课程 | 输入课程名称，上传 Markdown 原文与框架；支持不同课程使用不同材料 |
| 课程切换 | 在侧边栏选择课程，恢复该课程自己的聊天和学习位置 |
| 自然对话 | 接受中文输入，由模型根据资料、框架和上下文进行讲解、追问与回答 |
| 按框架学习 | 从大框架开始理解，再逐步深入；框架保持不变 |
| 用户控制推进 | 用户明确决定进入下一阶段；模型不得自行推进 |
| 持续记忆 | 保存对话、当前框架位置、未结束的问题和必要的学习摘要 |
| 课程进度 | 在课程列表显示课程学习进度；由用户确认推进；计算细节见第 5 节 |
| 个人账号展示 | 侧边栏顶部展示个人账号信息；认证方案另行确定 |

不包含：网页搜索、修改或自动生成框架、专门的真实场景指导、选择题、复习调度、笔记、整理与存放功能、应用内语音识别、多人协作。手机键盘的语音转文字可用于输入。普通对话中用户可以自由提问，但第一版不建设真实场景管理或指导模块。

## 3. 网络与模型

- 通过网络调用百炼 API；不搜索额外网上资料。联网调用模型与网页搜索是不同能力。
- 模型可以采用灵活表达、类比和追问，但课程事实应以用户资料为依据。资料不足时说明不足；额外解释不可伪装成原文观点。
- 相关资料与对话将发送给百炼处理。API Key 由服务端提供，不暴露给浏览器。
- 模型型号、兼容接口、上下文长度、调用预算、超时和重试参数在实现前确定。
- 第一版要求联网完成 AI 对话；离线浏览、离线模型和离线同步不属于已确认范围。

## 4. 界面规格

以用户提供的两屏 SVG 原型为视觉依据：白色背景、紫色强调色、简洁的通用大模型聊天布局。

### 主聊天区

- 顶栏包含侧边栏开关、当前课程名称及个人头像展示。
- 中部展示当前课程的用户与教练消息，支持阅读 Markdown 内容。
- 底部为中文输入框和发送按钮。保留用户输入，反馈生成中及失败状态。
- 手机端侧边栏默认可收起，为对话提供主要空间；展开时以抽屉覆盖部分聊天区，并可关闭。

### 课程侧边栏

- 顶部个人头像、名称及账号状态。原型中的姓名、邮箱是占位示例，不是真实身份配置。
- “添加新课程”按钮。
- 课程列表，显示名称、进度百分比及进度条；选择后切换到对应课程。
- 列表虽然沿用原型的“历史课程”标题，实际代表独立课程，不是历史对话列表。

### 创建课程

作为唯一必要的辅助流程，收集课程名称、Markdown 原文和 Markdown 框架，并清楚区分两种材料。界面形式可采用弹层或独立页面，在实现前选择。

原型中的跑步、英语和冥想课程只说明列表布局，不引入这些领域的专用能力。真实工作场景对话也仅作视觉示例。

## 5. 学习行为与进度

### 已确认行为与实现方向

- 用户自行决定是否继续，不需要考试或模型判定“真的学会”。进度表示确认走过的内容，不是知识掌握率。
- 使用外部标注的 Markdown 框架树组织学习，标注规则见 [Markdown 协议](MARKDOWN_PROTOCOL.md)。应用不修改框架，也不自动猜测资料关联。
- 两个阶段：`overview`（整体结构）和 `detail`（深入节点），另有 `finished` 表示全部单元完成。整体阶段给模型整个框架、概览引用资料；深入阶段给当前节点、框架位置、直接引用资料及对话记忆。
- 应用持久保存阶段、当前位置与未结束的问题，不依赖提示词或模型记忆维持状态。每次请求明确附带主线位置。
- 自由讨论不会改变主线位置。用户提出回到主线时，使用保存的位置和问题继续；摘要不能改写这些结构化状态。
- 模型可以提问、解释并指出疑问，但不能决定完成或阻止用户推进。

### 推进与进度的候选细节

推荐聊天框附近保留“下一步”按钮：整体阶段切换到深入阶段；深入阶段确认当前 lesson 完成并继续。纯聊天提出继续再确认也是备选。用户同意自己控制推进，但按钮形式尚未单独确定。

推荐按框架文档顺序访问 lesson，section 用于组织，overview 用于整体阶段。候选公式：`已由用户确认完成的 lesson 数 / 全部 lesson 数 × 100%`，overview/section 不计数。重复操作不重复计数；最后一个 lesson 完成后仍可讨论。遍历顺序、是否允许跳转和百分比取整仍需确认。

推进在应用中作为明确状态操作完成，不能由模型生成文本、材料中的指令或含糊对话触发。完成记录、当前位置和状态版本在同一事务提交；请求需有唯一操作标识及预期状态版本，避免重复点击或迟到请求跳过节点。外部模型标注不记录“已学会”或替用户确认进度。

## 6. 记忆与数据边界

每门课程独立保存：

- 课程标识、名称及创建信息。
- 用户上传的原文、框架及解析后的节点标识。
- 按顺序保存的用户和教练消息。
- 当前节点、用户确认完成的节点集合、未结束的问题。
- 为恢复上下文而生成的课程学习摘要；摘要不得覆盖原始消息或改变进度。

完整记录由持久化存储保存。模型上下文使用相关材料、摘要和近期消息，不假设完整课程永远能塞进一次请求。具体切分、检索和摘要策略应根据样例及模型限制选择。跨课程不得混入材料、摘要或对话。

个人长期背景、真实场景记忆、笔记等不属于第一版。持久化要求支持浏览器刷新、关闭后重新进入以及后端进程重启；仅保存在内存中不满足要求。

### SQLite 数据库设计

第一版采用 SQLite 作为单用户、单后端的设计方案，不增加独立数据库服务或向量数据库。目前仅为规格，尚未创建数据库。数据库必须放在持久磁盘；容器临时文件系统不能作为唯一存储，部署时配置备份与恢复。

| 表 | 主要字段与职责 |
| --- | --- |
| courses | id、name、created_at：课程身份 |
| documents | id、course_id、type、filename、markdown、content_hash：保存完整框架/资料文件 |
| framework_nodes | course_id、node_id、document_id、parent_node_id、title、node_type、position、body：框架树与排序 |
| material_blocks | course_id、material_id、document_id、title、body、source_ref：编号定位的资料块 |
| node_material_refs | course_id、node_id、material_id、position：有序多对多关联 |
| learning_sessions | course_id、phase、current_node_id、resume_question、summary、state_version：每课程一份当前学习状态 |
| node_progress | course_id、node_id、confirmed_at：用户确认完成记录，组合唯一 |
| messages | id、course_id、request_id、role、content、status、created_at：对话与请求归属 |

字段为逻辑设计，具体 SQL、迁移和索引在实现阶段确定。节点与资料使用课程内复合唯一键；关联及当前位置使用带 course_id 的复合外键，禁止跨课程引用。启用 SQLite 外键检查。聊天请求及推进操作分别维护幂等标识，避免失败重试产生重复状态；具体操作记录表按实现补充。

导入先完整校验，再事务保存文件、树、资料块和映射。查询通过 `(course_id, node_id)` 获取有序资料引用，再按 `(course_id, material_id)` 取正文，不做语义猜测。保留原始文件便于核对，解析结果不能覆盖源文件。

### 上下文构建

整体阶段读取框架结构与 overview 引用资料；深入阶段读取当前 lesson 与其资料引用、父节点路径及整体框架。再加入相关摘要、未结束的问题和近期聊天。引用定位是确定性的；关联之外的问题先用当前上下文讨论，资料不足时说明，不自动跨课程搜索或联网补资料。

按模型 token 预算选择与切分上下文，不能把所有引用无限拼接。预算不足时需说明内容覆盖限制或分轮讨论；块大小只是整理建议。摘要保存对话意义，不改变阶段、当前位置或完成集合。

## 7. 面向对象的职责建议

以下为设计边界建议，类名及实现技术尚未锁定：

| 职责 | 输入 | 输出与副作用 |
| --- | --- | --- |
| 课程服务 | 名称、材料及框架 | 创建课程、返回课程标识；持久化课程信息 |
| 材料导入器 | Markdown 文件内容 | 经校验的材料与节点结构；不重写框架 |
| 学习状态服务 | 课程标识、明确的用户推进决定 | 更新学习位置与完成集合；计算进度 |
| 对话教练 | 课程标识、用户消息及课程上下文 | 教练回复；保存消息和必要摘要 |
| 上下文构建器 | 当前课程材料、状态、相关记录 | 符合模型预算的上下文；不读取其他课程 |
| 模型适配器 | 消息上下文、模型参数 | 模型回复或结构化错误；调用百炼 |
| 存储接口 | 课程、消息和状态数据 | 持久读写；隔离具体数据库 |

核心状态规则由应用负责，不能只靠提示词保证。接口使用明确类型、错误语义与副作用说明。业务逻辑、模型供应商与持久化实现分离。

## 8. 异常与访问保护

- 无效或空材料给出可理解的错误，不创建半完成课程。
- 模型超时、限流或网络故障时允许用户重试，保留已输入内容，学习进度不变。
- 请求或页面重试不应重复记录同一轮消息或重复完成节点。
- 切换课程或较迟到达的模型回复必须归属原课程，不能污染当前课程。
- 不渲染 Markdown 内的可执行脚本或危险 HTML。
- 个人应用公开部署前需要访问保护；具体登录方式、账号恢复方式尚未确定。账号一栏只是界面需求，不意味着要建设完整多用户系统。

## 9. 技术方向与待定事项

建议采用适合手机的响应式网页/PWA，加轻量后端。它支持浏览器使用及主屏幕入口，无需原生 App 分发；此方案尚待技术确认。

实现前需要确定：

1. 用实际资料验证标注协议；确认 lesson 顺序、是否允许跳转及进度取整。
2. 每门课程上传文件数量、大小限制；第一版是否支持创建后的替换或删除。
3. 前后端语言、框架和低成本部署方式；SQLite 持久卷与备份安排。
4. 单用户登录/访问保护方案及账号展示内容。
5. 百炼模型、上下文预算、调用参数和凭据配置。
6. 下一步按钮或聊天二次确认的推进交互。

这些事项不阻碍规格整理，但不得在实现时悄悄扩大范围或假定已获确认。

## 10. 交付流程

先审阅本规格与 TDD 验收场景，确认待定的必要决策，再实现。每个功能遵循“失败测试 → 最小实现 → 重构”。第一版验收覆盖课程创建与切换、按框架对话、用户控制推进、记忆恢复、手机布局及真实百炼调用。尚未运行的验证不能作为交付证据。
