# 个人 AI 学习教练：规格与设计

状态：讨论结果整理稿，待用户审阅。更新日期：2026-10-10。

## 1. 产品定位

面向个人、适合手机碎片时间使用的中文 AI 学习教练。用户先在外部通用大模型中，将已有知识整理成符合自身思考习惯的框架，再将 Markdown 原文和框架导入本应用。应用依托通义千问（阿里云百炼）进行自然讲解、提问和讨论，沿既定框架从整体逐步深入，并保存学习位置。

第一版的核心价值是按框架持续学习及恢复上下文。用户决定何时进入下一阶段。应用不修改框架，也不以考试结果限制推进。

## 2. 已确认的第一版范围

| 功能 | 行为 |
| --- | --- |
| 创建课程 | 输入课程名称，上传 Markdown 原文与框架；支持不同课程使用不同材料 |
| 课程切换 | 在侧边栏选择课程，恢复该课程自己的聊天和学习位置 |
| 自然对话 | 接受中文输入，由模型根据资料、框架和上下文进行讲解、追问与回答 |
| 按框架学习 | 从大框架开始理解，再逐步深入；框架保持不变 |
| 用户控制推进 | 用户明确决定进入下一阶段；模型不得自行推进 |
| 持续记忆 | 保存对话、当前框架位置、未结束的问题和必要的学习摘要 |
| 课程进度 | 在课程列表显示课程学习进度；计算规则待讨论 |
| 个人账号展示 | 侧边栏顶部展示个人账号信息；认证方案另行确定 |

不包含：网页搜索、修改或自动生成框架、专门的真实场景指导、选择题、复习调度、笔记、整理与存放功能、应用内语音识别、多人协作。手机键盘的语音转文字可用于输入。普通对话中用户可以自由提问，但第一版不建设真实场景管理或指导模块。

## 3. 网络与模型

- 通过网络调用百炼 API；不搜索额外网上资料。联网调用模型与网页搜索是不同能力。
- 模型可以采用灵活表达、类比和追问，但课程事实应以用户资料为依据。资料不足时说明不足；额外解释不可伪装成原文观点。
- 相关资料与对话将发送给百炼处理。API Key 由服务端提供，不暴露给浏览器。
- 模型型号、兼容接口、上下文长度、调用预算、超时和重试参数在实现前确定。
- 第一版要求联网完成 AI 对话；离线浏览、离线模型和离线同步不属于已确认范围。

## 4. 界面规格

以用户提供的两屏 SVG 原型为视觉依据：白色背景、紫色强调色、简洁的通用大模型聊天布局。

### 主聊天区

- 顶栏包含侧边栏开关、当前课程名称及个人头像展示。
- 中部展示当前课程的用户与教练消息，支持阅读 Markdown 内容。
- 底部为中文输入框和发送按钮。保留用户输入，反馈生成中及失败状态。
- 手机端侧边栏默认可收起，为对话提供主要空间；展开时以抽屉覆盖部分聊天区，并可关闭。

### 课程侧边栏

- 顶部个人头像、名称及账号状态。原型中的姓名、邮箱是占位示例，不是真实身份配置。
- “添加新课程”按钮。
- 课程列表，显示名称、进度百分比及进度条；选择后切换到对应课程。
- 列表虽然沿用原型的“历史课程”标题，实际代表独立课程，不是历史对话列表。

### 创建课程

作为唯一必要的辅助流程，收集课程名称、Markdown 原文和 Markdown 框架，并清楚区分两种材料。界面形式可采用弹层或独立页面，在实现前选择。

原型中的跑步、英语和冥想课程只说明列表布局，不引入这些领域的专用能力。真实工作场景对话也仅作视觉示例。

## 5. 学习行为与进度（具体方案待讨论）

本节保留此前的候选方案作为讨论材料，不作为已批准的实现规则。已确认的是：从整体到局部、框架不修改、用户决定推进、可恢复学习位置、课程显示进度。节点划分、遍历方式、推进交互与进度计算仍需讨论。

### 候选流程

1. 用户创建课程，应用校验材料并建立框架节点结构。
2. 首次学习先概览整体结构，以适合用户的提问帮助理解节点之间的关系。
3. 在当前节点进行讲解、提问、回答和讨论。遇到不理解时可以解释或提供提示，不因回答一次就认定完成。
4. 用户可偏离当前问题进行讨论，之后仍能回到原学习位置；自由讨论不会自行改变进度。
5. 用户明确确认当前节点完成并要求继续时，应用更新完成记录和当前位置。
6. 用户离开后，聊天、学习位置和未结束的问题持久保存。再次进入恢复原课程上下文。

候选进度公式（尚未确认）：`用户确认完成的可学习节点数 / 全部可学习节点数 × 100%`。重复确认不能重复计数。进度代表走完框架的比例，不代表模型测得的知识掌握率。概览、目录等结构节点是否参与计数、百分比取整方式需要结合实际框架确认。

“进入下一节”的自然语言交互是候选方案；是否采用自然语言、按钮或二次确认仍需讨论。含糊表达、引用资料中的指令或模型自身建议不得触发推进。最后一个节点完成后显示课程已完成，仍允许继续讨论。

## 6. 记忆与数据边界

每门课程独立保存：

- 课程标识、名称及创建信息。
- 用户上传的原文、框架及解析后的节点标识。
- 按顺序保存的用户和教练消息。
- 当前节点、用户确认完成的节点集合、未结束的问题。
- 为恢复上下文而生成的课程学习摘要；摘要不得覆盖原始消息或改变进度。

完整记录由持久化存储保存。模型上下文使用相关材料、摘要和近期消息，不假设完整课程永远能塞进一次请求。具体切分、检索和摘要策略应根据样例及模型限制选择。跨课程不得混入材料、摘要或对话。

个人长期背景、真实场景记忆、笔记等不属于第一版。持久化要求支持浏览器刷新、关闭后重新进入以及后端进程重启；仅保存在内存中不满足要求。

## 7. 面向对象的职责建议

以下为设计边界建议，类名及实现技术尚未锁定：

| 职责 | 输入 | 输出与副作用 |
| --- | --- | --- |
| 课程服务 | 名称、材料及框架 | 创建课程、返回课程标识；持久化课程信息 |
| 材料导入器 | Markdown 文件内容 | 经校验的材料与节点结构；不重写框架 |
| 学习状态服务 | 课程标识、明确的用户推进决定 | 更新学习位置与完成集合；计算进度 |
| 对话教练 | 课程标识、用户消息及课程上下文 | 教练回复；保存消息和必要摘要 |
| 上下文构建器 | 当前课程材料、状态、相关记录 | 符合模型预算的上下文；不读取其他课程 |
| 模型适配器 | 消息上下文、模型参数 | 模型回复或结构化错误；调用百炼 |
| 存储接口 | 课程、消息和状态数据 | 持久读写；隔离具体数据库 |

核心状态规则由应用负责，不能只靠提示词保证。接口使用明确类型、错误语义与副作用说明。业务逻辑、模型供应商与持久化实现分离。

## 8. 异常与访问保护

- 无效或空材料给出可理解的错误，不创建半完成课程。
- 模型超时、限流或网络故障时允许用户重试，保留已输入内容，学习进度不变。
- 请求或页面重试不应重复记录同一轮消息或重复完成节点。
- 切换课程或较迟到达的模型回复必须归属原课程，不能污染当前课程。
- 不渲染 Markdown 内的可执行脚本或危险 HTML。
- 个人应用公开部署前需要访问保护；具体登录方式、账号恢复方式尚未确定。账号一栏只是界面需求，不意味着要建设完整多用户系统。

## 9. 技术方向与待定事项

建议采用适合手机的响应式网页/PWA，加轻量后端。它支持浏览器使用及主屏幕入口，无需原生 App 分发；此方案尚待技术确认。

实现前需要确定：

1. 一份实际 Markdown 框架的格式、节点层级、可学习节点及遍历顺序。
2. 每门课程上传文件数量、大小限制；第一版是否支持创建后的替换或删除。
3. 前后端语言、框架、持久化存储和低成本部署方式。
4. 单用户登录/访问保护方案及账号展示内容。
5. 百炼模型、上下文预算、调用参数和凭据配置。
6. 用户推进意图的确认方式，以及进度展示的取整规则。

这些事项不阻碍规格整理，但不得在实现时悄悄扩大范围或假定已获确认。

## 10. 交付流程

先审阅本规格与 TDD 验收场景，确认待定的必要决策，再实现。每个功能遵循“失败测试 → 最小实现 → 重构”。第一版验收覆盖课程创建与切换、按框架对话、用户控制推进、记忆恢复、手机布局及真实百炼调用。尚未运行的验证不能作为交付证据。
